# TRAE（TraeWork / TraeCode）记忆系统设计说明

> 本文档说明 TRAE 记忆系统的完整设计，包含**产品功能层面**与**实际落地实现层面**两部分。

## 一、产品功能层面（官方设计）

官方文档：[记忆功能](https://docs.trae.cn/work/memories)

### 1. 记忆类型与作用域

记忆系统采用**双层作用域**设计：

| 类型 | 生效范围 | 存储位置 |
|---|---|---|
| 全局记忆 | 当前用户本地的所有项目 | macOS/Linux：`~/.trae-cn/memory/user_profile.md`；Windows：`%userprofile%\.trae-cn\memory\user_profile.md` |
| 项目记忆 | 仅当前项目的当前用户 | `~/.trae-cn/memory/projects/{project_path}/project_memory.md`（Windows 同理） |

### 2. 核心规则

- **本地存储**：记忆只存在本机，不跨电脑共享、不上传。
- **选择性保存**：以下内容**不会**自动保存为记忆（除非用户明确要求）：
  - 一次性或临时指令
  - 模糊、不确定的偏好
  - 敏感信息（密码、个人隐私）
- **启用位置**：设置 > 规则与记忆 > 记忆，打开开关。

### 3. 管理方式（双通道写入）

- **手动通道**：在设置中点击"用户记忆 / 项目记忆"，在本地编辑器中打开 `user_profile.md` / `project_memory.md` 增删改。
- **AI 自动通道**：通过对话让 AI 管理，包括：
  - 自动创建（识别对后续协作有价值的偏好/规则）
  - 自动更新（偏好变化时主动修改）
  - 按要求创建/修改/删除（如"记住我偏好用中文回答"、"以后叫我 David"、"删除关于称呼的记忆"）

## 二、实际落地实现层面

AI 运行时真实维护的目录结构：

```text
~/.trae-cn/memory/
├── user_profile.md                     # 用户级（全局记忆）：跨项目的偏好、背景、技术栈
└── projects/
    └── {项目路径哈希化目录}/           # 每个项目一个独立目录
        ├── project_memory.md           # 项目级：规则、约束、约定、经验教训
        ├── topics.md                   # 主题级：目标、进度、决策（含 session_id 索引）
        └── {YYYYMMDD}/                 # 按日期分区
            └── session_memory_{chat_session_id}.jsonl   # 消息级：细化任务、TODO、相关文件
```

### 分层粒度设计（四级金字塔）

1. **消息级**（`session_memory_*.jsonl`）：最小粒度，按会话记录任务、TODO、涉及文件，是检索的最底层来源。
2. **主题级**（`topics.md`）：跨会话聚合，记录目标、进度、决策，并保留 `[session_id: xxx | time]` 索引以便钻取原始会话。
3. **项目级**（`project_memory.md`）：只作用于当前项目，用于固化项目特有的规则/约定。
4. **用户级**（`user_profile.md`）：跨所有项目生效，是全局记忆的实现载体。

### 检索决策机制（什么时候用记忆）

- **跳过记忆**：请求自包含、不依赖历史（如查时间、简单翻译、一次性命令）。
- **默认使用**：涉及工作区/模块/路径、请求前后一致性、任务含糊可能依赖早期决策、非平凡任务。
- 检查流程为轻量级：先看 `project_memory.md` 和近期 `topics.md` → 按关键词 grep 记忆文件 → 命中 session_id 再钻取对应 jsonl，全程控制在几步内。

### 写入规则

- 用户说"记住我的 xxx"时：用户级信息（偏好、技术栈）追加到 `user_profile.md`；项目级信息（规则、约束、约定）追加到 `project_memory.md`。

## 三、设计要点总结

1. **本地优先 + 隐私保护**：所有记忆明文存本地，不云同步、不共享，敏感信息默认不记。
2. **作用域隔离**：全局/项目双层，避免跨项目污染。
3. **多级粒度**：消息 → 主题 → 项目 → 用户，兼顾检索效率与持久性。
4. **双通道维护**：用户手动编辑 + AI 自动识别/更新，配合时间分区的 JSONL 保留历史可回溯性。
5. **选择性写入**：临时/模糊/敏感信息不自动入记忆，防止记忆膨胀和隐私泄漏。
